# Operator community

Join the [Operator Discord](https://discord.gg/p4aaXvzJq2) for real-time conversation,
quick help, showcases, and contributor discussion. GitHub remains the canonical record for
bugs, feature proposals, technical decisions, and releases so they stay searchable and
connected to the work.

## Where to go

| You want to… | Use |
|-|-|
| Chat with users and contributors | [Operator Discord](https://discord.gg/p4aaXvzJq2) |
| Propose or vote on a feature | [Ideas in GitHub Discussions](https://github.com/iishyfishyy/operator-oss/discussions/categories/ideas) |
| Ask for help | [Q&A in GitHub Discussions](https://github.com/iishyfishyy/operator-oss/discussions/categories/q-a) |
| Show what you built | [Show and tell](https://github.com/iishyfishyy/operator-oss/discussions/categories/show-and-tell) |
| Report a reproducible bug | [Bug report](https://github.com/iishyfishyy/operator-oss/issues/new?template=bug_report.yml) |
| Fix or improve Operator | [Contributing guide](../CONTRIBUTING.md) |
| Report a vulnerability | [Security policy](../SECURITY.md) |

Please search before opening a new thread. Add the problem you are solving, your current
workaround, and why the outcome matters; that context is more useful than a proposed UI
alone.

## How ideas become features

1. New ideas begin in Discussions, where others can add use cases and vote.
2. Maintainers triage ideas as **Considering**, **Planned**, **Needs evidence**, or
   **Not planned**.
3. Accepted ideas become scoped GitHub issues before implementation begins.
4. The issue and pull request link back to the original discussion.
5. Release notes close the loop when the feature ships.

The roadmap is directional, not a promise. A focused pull request may ship before a popular
idea when it is safer or unlocks other work.

Maintainers review new threads weekly. A lightweight public project can track only accepted
work under **Now**, **Next**, and **Later**; uncommitted ideas stay in Discussions until
their problem and scope are clear.

## Community standards

Be respectful, constructive, and curious. Critique ideas and code, not people. Do not post
private repository content, credentials, or security reports in public channels.

For contribution mechanics, tests, and the Developer Certificate of Origin, see
[CONTRIBUTING.md](../CONTRIBUTING.md).
